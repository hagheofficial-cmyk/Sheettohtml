# سامانه QC مستقل روی Google Sheets (Apps Script)

این پوشه نسخه‌ی **کاملاً مستقل** سامانه است: یک Web App در Google Apps Script که لینک اختصاصی دارد،
رابط کامل CRM را سرو می‌کند و همه‌ی داده‌ها را مستقیماً در **تب‌های جداگانه‌ی همان Google Sheet**
نگه می‌دارد. در این حالت هیچ سرور Node، هیچ میزبان و هیچ پوشه‌ی محلی لازم نیست.

> تفاوت با `crm-qc/apps-script/Code.gs`: آن نسخه فقط یک API/گزارش سبک برای اتصالِ نسخه‌ی Node به شیت بود.
> این نسخه (`apps-script-full`) خودِ سامانه است.

---

## فایل‌های این پوشه

| فایل | نقش | اندازه |
|---|---|---|
| `Code.gs` | بک‌اند Apps Script: خواندن/نوشتن تب‌ها، روتر API، منوی شیت، `doGet` | ~178 KB |
| `Index.html` | رابط کامل سامانه (همه‌ی صفحه‌ها، نمودارها، استایل و فونت) | ~760 KB |
| `CallReport.html` | ابزار مستقل «گزارش تماس روزانه» که داخل برگه‌ی گزارش تماس باز می‌شود | ~390 KB |
| `appsscript.json` | مانیفست پروژه (منطقه زمانی، دامنه دسترسی، تنظیمات Web App) — برای استقرار با `clasp` | — |
| `Server.gs` | **فایل منبع** بک‌اند (مستقیم در Apps Script کپی نشود؛ build از آن `Code.gs` را می‌سازد) | — |

این فایل‌ها خروجی build هستند. دو طعم وجود دارد:

| build | دستور | کتابخانه‌ها | کاربرد |
|---|---|---|---|
| پیش‌فرض (CDN) | `npm --prefix crm-qc run build:apps-script` | Chart.js/SheetJS/ExcelJS/html2canvas/jsPDF/JSZip/Font Awesome/وزیرمتن از jsDelivr | فایل‌ها سبک‌اند و **راحت در ویرایشگر Apps Script paste می‌شوند**؛ برای باز شدن به اینترنت نیاز دارند |
| آفلاین | `npm --prefix crm-qc run build:apps-script:offline` → `apps-script-full/offline/` | همه‌چیز داخل فایل جاسازی می‌شود | بدون هیچ درخواست خارجی؛ فایل‌ها چند مگابایت‌اند و عملاً فقط با `clasp push` قابل استقرارند |

برای ساخت دوباره پس از هر تغییر در `crm-qc/public` یا `crm-qc/shared`:

```bash
npm --prefix crm-qc ci          # فقط بار اول (نسخه‌ی کتابخانه‌ها از node_modules خوانده می‌شود)
npm --prefix crm-qc run build:apps-script
```

## فعال‌سازی، گام به گام

### ۱) شیت و پروژه‌ی اسکریپت

1. یک Google Sheet تازه بسازید (یا شیت موجود را باز کنید). این شیت **دیتابیس** سامانه می‌شود.
2. از منوی شیت: `Extensions → Apps Script`.
3. در ویرایشگر، سه فایل بسازید با **دقیقاً همین نام‌ها**:
   - `Code.gs` → محتوای `apps-script-full/Code.gs` (کد پیش‌فرض `Code.gs` را کامل جایگزین کنید)
   - `Index.html` → از `+ → HTML` با نام `Index` و محتوای `apps-script-full/Index.html`
   - `CallReport.html` → از `+ → HTML` با نام `CallReport` و محتوای `apps-script-full/CallReport.html`
4. هر سه را `Save` کنید (Ctrl+S).

> **نکته‌ی اندازه‌ی فایل:** فایل‌های همین پوشه (build پیش‌فرض) سبک‌اند و معمولاً بدون مشکل در ویرایشگر paste
> می‌شوند. اگر از build آفلاین (`apps-script-full/offline/`) استفاده می‌کنید یا ویرایشگر هنگ کرد، روش `clasp`
> در انتهای همین صفحه فایل‌ها را بدون paste مستقیم منتقل می‌کند.

### ۲) راه‌اندازی تب‌های دیتابیس

1. در نوار بالای ویرایشگر، تابع `setupStandaloneApp` را انتخاب و `Run` بزنید.
2. اولین بار، گوگل درخواست اجازه می‌کند: `Review permissions` → حساب خودتان → `Advanced` →
   `Go to <project name> (unsafe)` → `Allow`. (پیام «unsafe» فقط چون برنامه توسط خودتان نوشته شده است.)
3. شیت را refresh کنید. تب‌های زیر ساخته می‌شوند و منوی **سامانه QC مستقل** به شیت اضافه می‌شود:

| تب | محتوا |
|---|---|
| `Agents` | کارشناسان: شناسه، داخلی، نام، تیم، فعال، زیرگروه، aliasها |
| `Tickets` | ارزیابی تیکت: ریز المان‌ها، ردلاین، نمره، تاریخ بررسی/تیکت، کارشناس QC |
| `Socials` | ارزیابی سوشال: تاریخ/ساعت دریافت و پاسخ، SLA، مدت کاری، المان‌ها، نمره |
| `Calls` | ریت تماس: نمره، ردلاین، المان‌ها، فرم/تیم، فایل و ردیف منبع |
| `QC_Agents` | فهرست کارشناسان کنترل کیفیت |
| `Actions` | اقدامات اصلاحی (با ستون `agent`) |
| `Reminders` | یادآورهای کارشناس |
| `Action_Types` | نوع اقدام‌ها |
| `Settings` | وزن‌ها، آستانه SLA، ساعت کاری، روزهای تعطیل، نام سازمان (کلید/مقدار) |
| `Lists` | فهرست‌های کشویی (پیام‌رسان، وضعیت پاسخ، دلیل تأخیر) |
| `Criteria` | تعریف المان‌های ریت تماس هر تیم/فرم (JSON) |
| `Meta` | `datasetId`، `createdAt`، شمارنده‌های `seq` |
| `Call_Metadata` | متادیتای ایمپورت تماس‌ها (`callImport`, `callSync`, `callRaw`) |
| `Call_Report_Experts` / `Call_Report_Access` | تنظیمات ابزار گزارش تماس روزانه |

اگر شیت از قبل داده داشته باشد، `setupStandaloneApp` آن را **پاک نمی‌کند**؛ فقط ساختار را کامل می‌کند و
داده‌ی موجود را می‌خواند. دیتای نمونه (`data/seed.json`: ۶۵ کارشناس و تنظیمات پیش‌فرض) فقط وقتی شیت
کاملاً خالی است نوشته می‌شود.

### ۳) ساخت لینک اختصاصی (Deploy)

1. در ویرایشگر: `Deploy → New deployment`.
2. کنار چرخ‌دنده نوع استقرار را `Web app` انتخاب کنید.
3. `Description`: مثلاً «سامانه QC — نسخه ۱».
4. `Execute as`: **Me** (حساب خودتان؛ دسترسی شیت از اعتبار شما می‌آید).
5. `Who has access`: بر اساس سیاست سازمان —
   - `Only myself` = فقط شما (امن‌ترین حالت برای تست)،
   - `Anyone within <domain>` = همکاران دامنه‌ی سازمانی (پیشنهادی)،
   - `Anyone` = هر کسی با لینک؛ فقط در صورت مجاز بودن استفاده کنید.
6. `Deploy` → `Authorize access` (اگر خواست) → **Web app URL** را کپی کنید.

همان URL، لینک مستقل سامانه است؛ مثل یک سایت باز می‌شود و می‌توانید آن را بوک‌مارک یا در موبایل
«Add to Home Screen» کنید.

### ۴) تست سریع

- لینک را باز کنید: باید داشبورد با داده‌ی شیت بالا بیاید و نشانگر بالای صفحه **Google Sheets** باشد.
- یک ارزیابی تیکت یا سوشال ثبت کنید → بلافاصله ردیف جدید در تب `Tickets` / `Socials` ظاهر می‌شود.
- مستقیم در شیت یک ردیف اضافه/ویرایش کنید → در سامانه `Refresh` بزنید؛ تغییر خوانده می‌شود.
- منوی شیت: `سامانه QC مستقل → راه‌اندازی / بررسی تب‌های سامانه` همان `setupStandaloneApp` است.

## رفتار داده در این نسخه

- **شیت تنها منبع داده است.** هر درخواست API وضعیت فعلی تب‌ها را می‌خواند، منطق ثبت/نمره‌دهی اجرا می‌شود
  و فقط تب‌هایی که واقعاً تغییر کرده‌اند بازنویسی می‌شوند.
- **نوشتن هم‌زمان:** همه‌ی درخواست‌ها با `LockService` قفل می‌شوند؛ اگر دو نفر هم‌زمان ثبت کنند، درخواست
  دوم تا ۳۰ ثانیه منتظر می‌ماند و بعد روی داده‌ی تازه اجرا می‌شود.
- **ورود اکسل ریت تماس:** پوشه‌ی محلی `data/calls` در این نسخه وجود ندارد. از برگه‌ی **مرکز داده**
  فایل‌های `.xlsx` را آپلود کنید؛ همان منطق تشخیص فرم/تیم و ادغام امن اجرا و نتیجه در تب `Calls` نوشته می‌شود.
- **بک‌اپ:** از برگه‌ی مرکز داده خروجی JSON بگیرید، یا یک کپی از خود شیت (`File → Make a copy`) نگه دارید.
- **تاریخ‌ها** به همان شکل جلالی `1405/07/22` در تب‌ها ذخیره می‌شوند. ستون‌های JSON (مثل `elements`) را
  دستی نشکنید.

## محدودیت‌هایی که باید بدانید

- Google Sheets برای حجم کم تا متوسط مناسب است؛ سهمیه‌ی اجرای Apps Script و محدودیت نرخ API دارد.
  با چند هزار ردیف مشکلی نیست، اما برای بار سنگین/چند کاربر هم‌زمان دیتابیس واقعی بهتر است.
- **احراز هویت کاربری وجود ندارد:** هر کس به لینک دسترسی داشته باشد، کل داده را می‌بیند و می‌تواند بنویسد.
  سطح دسترسی را در مرحله‌ی Deploy کنترل کنید.
- هر تغییر در کد، نیاز به `Deploy → Manage deployments → Edit → New version` دارد تا روی لینک اعمال شود.
- ابزار «گزارش تماس روزانه» تنظیمات خودش (کارشناسان/پروفایل دسترسی) را در دو تب اختصاصی نگه می‌دارد.

## استقرار با `clasp` (وقتی فایل‌ها برای paste بزرگ‌اند)

```bash
npm install -g @google/clasp
clasp login
cd crm-qc/apps-script-full
clasp create --type sheets --title "سامانه QC" --rootDir .   # یا clasp clone <scriptId>
clasp push                                                   # هر سه فایل + appsscript.json
clasp open
```

سپس در ویرایشگر `setupStandaloneApp` را اجرا و طبق بخش ۳ استقرار Web App را بسازید.

## اگر خواستید هر دو نسخه را داشته باشید

نسخه‌ی Node (با پوشه‌ی `data/calls` و واچر خودکار) همچنان کار می‌کند و از تب **اتصال به گوگل شیت**
(`#/sheets`) به یک شیت وصل می‌شود؛ آن مسیر از `crm-qc/apps-script/Code.gs` استفاده می‌کند و به این
پوشه ربطی ندارد. برای جلوگیری از دو منبع داده، یکی از دو حالت را انتخاب کنید:

- فقط Apps Script مستقل (این پوشه) — بدون سرور،
- یا فقط Node + شیت به‌عنوان مخزن/گزارش.
