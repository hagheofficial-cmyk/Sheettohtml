# سامانه یکپارچه کنترل کیفیت CRM (CRM QC System)

سیستم کامل QC برای تیم CRM که سه بخش را یکجا جمع می‌کند:

| بخش | مسیر | توضیح |
|---|---|---|
| داشبورد | `#/dashboard` | شاخص‌های زنده، توزیع نمرات، وضعیت SLA، آخرین ارزیابی‌ها |
| ارزیابی تیکت | `#/tickets` | ثبت/ویرایش/حذف ارزیابی تیکت با محاسبه نمره بر اساس فرمول اکسل + خروجی اکسل |
| ارزیابی سوشال | `#/socials` | ثبت ارزیابی پیام‌رسان‌ها با محاسبه **مدت پاسخگویی در ساعات کاری** و **SLA** + خروجی اکسل |
| گزارش‌ها | `#/reports` | گزارش کارشناس/تیم (معادل Agent Report و Team Report اکسل) + نمودار + خروجی اکسل |
| ریت تماس | `#/feedback` | پنل اصلی ریت پروژه — **بدون هیچ تغییری** داخل سیستم سرو می‌شود |
| مدیریت پایه | `#/directory` | کارشناسان، کارشناسان QC و تنظیمات فرمول‌ها (وزن، SLA، ساعت کاری) |

## اجرا

```bash
cd crm-qc && npm install     # فقط بار اول — برای خواندن اکسل‌های QC از پوشه (xlsx)
node crm-qc/server.js        # پورت 8000 → http://localhost:8000
# یا با پورت دلخواه:  PORT=9000 node crm-qc/server.js
```

فقط Node ≥ 18. کتابخانه‌های فرانت (Chart.js، SheetJS، فونت) از CDN لود می‌شوند. بسته‌ی npm `xlsx` فقط برای اسکنر سمت سرور لازم است (پوشه data/calls)؛ بدون آن هم سیستم کار می‌کند ولی اکسل‌های پوشه خوانده نمی‌شوند.

## اتصال پوشه اکسل‌های ریت (مهم)

فایل‌های فرم QC تیم‌های تلفنی/اکانت/MLM را در پوشه `crm-qc/data/calls/` بگذارید — سرور **هر ۱۵ ثانیه** خودش پوشه را جارو می‌کند و دیتای هر فایل را با دیتای داخل سامانه **ادغام و محاسبه** می‌کند (جدول روزانه، تفکیک فایل، میانگین تیم‌ها، ردلاین، پرونده‌ی هر کارشناس). کارت وضعیت پوشه هم در صفحه «ریت تماس» هر لحظه آخرین فایل‌های همگام‌شده را نشان می‌دهد. آپلود از داخل مرورگر هم در همان کارت پشتیبانی می‌شود. detailed docs ➜ ([data/calls/README.md](data/calls/README.md))

## فرمول‌های پیاده‌سازی‌شده (دقیقاً معادل اکسل‌های مرجع)

### نمره تیکت — ستون L شیت Evaluations
```
نمره = IF(هرکدام از G..K خالی → "":IF(K=0 → 0:
          SUMPRODUCT((G..J=1) × وزن) / SUMPRODUCT((G..J≠"-") × وزن) × 100)
وزن‌ها: ۴۰، ۲۰، ۲۰، ۲۰ — ردلاین (K) صفر ⇒ نمره نهایی صفر
```
### مدت پاسخگویی سوشال — ستون L (LET/MAP/SEQUENCE)
```
دقیقه‌های داخل پنجره کاری ۹:۰۰ تا ۱۸:۰۰ فقط در روزهای کاری (پنجشنبه/جمعه تعطیل)
بین تاریخ+ساعت دریافت تا تاریخ+ساعت پاسخ. پاسخ قبل از دریافت → «خطای تاریخ»
```
### وضعیت SLA — ستون O
```
عدم پاسخ → «بدون پاسخ» | اطلاعات ناقص → «اطلاعات ناقص»
| زمان ≤ ۶۰ دقیقه → «رعایت شده» | در غیر این صورت → «رعایت نشده»
```
### نمره سوشال — الگوی ستون U
```
همین فرمول وزنی با وزن‌های ۳۰، ۳۰، ۲۵، ۱۵ (SLA / پیگیری / پایان‌بندی / لحن)
```
### گزارش‌ها
- نرخ هر المان = `۱۰۰ × تعداد(۱) / (تعداد(۱)+تعداد(۰))` — «نامرتبط» نادیده گرفته می‌شود
- رعایت واقعی SLA = `رعایت‌شده / (رعایت‌شده + رعایت‌نشده)`
- میانگین نمره فقط روی ارزیابی‌های نمره‌دار

تاریخ جلالی ↔ میلادی: الگوریتم استاندارد Jalaali (چرخه ۳۳ ساله) + Fourmilab — با کلیه نگاشت‌های شیت DATA اکسل تست‌شده.

### کش مرورگر و سرعت

- پاسخ‌های خواندنی صفحه‌ها برای هر توکن و آدرس/فیلتر جداگانه تا ۱۲۰ ثانیه در حافظه و `sessionStorage` همان تب نگهداری می‌شوند؛ پس از انقضا در درخواست بعدی دوباره خوانده می‌شوند. این کش فقط برای نشست توکن‌دار آنلاین است و با بستن تب از بین می‌رود.
- هنگام بازخوانی صفحه ابتدا نشست با سرور بررسی می‌شود؛ تغییر نقش یا محدودهٔ دسترسی، خروج و نشست نامعتبر کش را پاک می‌کند. داده‌های کش‌شده در مرورگر قابل دسترسی‌اند؛ روی دستگاه مشترک حتماً از حساب خارج شوید.
- هر عملیات ثبت/ویرایش/حذف کش را باطل می‌کند (حتی درخواست‌های قدیمیِ در حال اجرا نمی‌توانند دوباره آن را پر کنند). تغییر تب دیگر نیز از طریق مرورگر و تغییر سرور/شیت با بررسی نسخه حدود هر ۴۵ ثانیه تشخیص داده می‌شود؛ دکمهٔ تازه‌سازی داده را از سرور می‌خواند. تغییرات دیگران ممکن است تا بررسی بعدی یا حداکثر انقضای کش دیده نشوند.
- ورود، اعتبار نشست، نسخهٔ داده، تنظیمات حساس و درخواست‌های ناموفق کش نمی‌شوند. نوشتن‌ها همچنان منتظر تأیید سرور هستند؛ سرعت بارگذاری اولیه و ثبت به حجم داده، سرعت شبکه و Google Apps Script وابسته است و زمان ۱–۲ ثانیه برای همهٔ شرایط تضمین نمی‌شود.
- در نسخهٔ Apps Script پس از به‌روزرسانی فایل‌های خروجی، استقرار Web App را به نسخهٔ جدید به‌روزرسانی کنید.

### قراردادهای احراز هویت و هم‌زمانی

- در نسخهٔ Node/آفلاین تا وقتی کاربر فعال رمزدار نیست، حالت پیش‌فرض ورود را خاموش می‌کند؛ اما در نسخهٔ Apps Script ورود همواره اجباری است و مدیر اولیه فقط از داخل شیت ساخته می‌شود.
- پس از ساخت اولین مدیر در Node، هر درخواست (به‌جز `auth/*`، `bootstrap` و `revision`) به توکن نیاز دارد:
  `401` بدون نشست، `403` برای صفحه‌ها/APIهای مدیریتی وقتی نقش `qc` است.
- کارشناس QC همه‌ی خواندن‌ها را روی **کپی محدودشده**ی داده می‌گیرد (اتحاد `exts`/`agents`/`teams`)؛
  نوشتن هم فقط برای کارشناسان مجاز خودش اجازه دارد.
- `PUT /api/tickets/:id` و `PUT /api/socials/:id` اگر `baseUpdatedAt` کهنه بفرستند و رکورد در این فاصله
  ویرایش شده باشد، `409` با `{ conflict: { current } }` برمی‌گردانند؛ کلاینت گفت‌وگوی «بارگذاری نسخه‌ی
  تازه / جایگزینی تغییرات من» نشان می‌دهد و با `overwrite: true` ذخیره می‌کند.
- `PUT /api/criteria` با `version` کهنه → `409` (ویرایش هم‌زمان المان‌ها).

دیتای نمونه دمو: `node scripts/demo-seed.js`

## صفحه‌ها و قابلیت‌های مدیریتی

| صفحه | مسیر | چه کسی |
|---|---|---|
| مدیریت QC | `#/qcadmin` | فقط مدیر: ساخت کاربر، رمز، نقش، فعال/غیرفعال و تعیین داخلی‌ها/کارشناسان/تیم‌های مجاز هر کارشناس QC، حالت ورود (`auto`/`on`/`off`)، خروجی اکسل |
| تغییر المان‌ها | `#/criteria` | فقط مدیر: نام فارسی و ستون اکسل هر المان (روی شیت هم قابل ویرایش است) |
| مدیریت پایه | `#/directory` | فقط مدیر: کارشناسان QC، فهرست‌ها و **ویرایشگر ماه‌های مالی** (ساخت خودکار ۱۲ ماه) |
| مدیریت کارشناسان | `#/agents` | فقط مدیر |
| مرکز داده | `#/data` | فقط مدیر: ایمپورت اکسل، بک‌اپ، پاک‌سازی |
| داشبورد/گزارش‌ها/سوابق/ثبت ارزیابی/پرونده/مرجع/تحلیل تماس | — | مدیر با همه‌ی داده‌ها؛ کارشناس QC با داده‌ی محدودشده |

نکته‌های رابط:

- **منوی همبرگری** در همه‌ی اندازه‌ها پیش‌فرض بسته است و با کلیک (یا `Escape`، کلیک روی پس‌زمینه،
  دکمه‌ی بستن و رفتن به صفحه‌ی دیگر) باز و بسته می‌شود.
- **فیلتر تاریخ بالا** دکمه‌ی «اعمال بازه» ندارد: با `Enter`، تغییر فیلد یا انتخاب «بازه آماده» اعمال
  می‌شود. گزینه‌های ماه مالی از تب `Fiscal_Months` شیت می‌آیند (`ماه مالی جاری`، `ماه مالی قبل` و هر ماه
  جدا). کنار فیلدهای تاریخ، تقویم جلالی باز می‌شود.
- **ثبت ارزیابی:** نام کارشناس QC از کاربر واردشده می‌آید (برای نقش `qc` قفل است)، فیلد «نام کارشناس»
  کمبوی جستجو با پیشنهاد و پیمایش با کلیدهای بالا/پایین و `Enter` است، و کنار فیلدهای تاریخ تقویم هست.
- **همگام‌سازی:** نشانگر بالای صفحه هر ~۴۵ ثانیه `revision` را می‌پرسد؛ اگر کاربر دیگری داده را تغییر
  داده باشد، با یک کلیک داده‌ی تازه بارگذاری می‌شود. تنظیمات محلی هر کاربر (بازه، فیلترها، ستون‌ها) با
  کلید اختصاصی همان کاربر ذخیره می‌شود.
- **گزارش تماس:** در نسخه‌ی Node داخل یک فریم هم‌ریشه باز می‌شود. در نسخه‌ی Apps Script هم ابزار از
  خودِ سامانه با `google.script.run` گرفته و داخل یک فریم محلی (`srcdoc`) نمایش داده می‌شود؛ دیگر لازم
  نیست آدرس `/exec` در تب جدید باز شود، پس خطای «Sorry, unable to open the file at this time» رخ نمی‌دهد.
  بازه‌ی تاریخ و حالت رنگ هم به همان فریم منتقل می‌شوند.

## اتصال Google Sheets

از مسیر `#/sheets` می‌توانید Apps Script Web App (دوسویه)، Service Account یا API Key (فقط خواندن) را تنظیم کنید. جهت اولین همگام‌سازی باید صریحاً انتخاب شود؛ تا آن زمان داده‌ای به شیت یا از شیت به‌طور خودکار منتقل نمی‌شود. راهنمای کامل، کد Apps Script و نکات پشتیبان‌گیری/امنیت در [`apps-script/README.md`](apps-script/README.md) است. تنظیمات و کلیدها در `data/sheets-config.json` و `data/sheets-credentials.json` روی سرور نگهداری و از Git مستثنا شده‌اند.

## نسخه‌ی مستقل روی شیت (بدون سرور Node)

`apps-script-full/` یک Web App کامل Apps Script است: لینک اختصاصی، رابط کامل سامانه و دیتابیس روی تب‌های خودِ شیت (تیکت، سوشال و ریت تماس هرکدام تب جدا). ساخت خروجی:

```bash
npm --prefix crm-qc run build:apps-script    # Code.gs + Index.html + CallReport.html
```

راهنمای نصب، اجرای `setupStandaloneApp`، انتشار Web App و استقرار با `clasp` در [`apps-script-full/README.md`](apps-script-full/README.md). تست اجرایی بک‌اند مستقل با شبیه‌ساز شیت: `test/appsScriptStandalone.test.js`.
